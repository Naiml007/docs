Skills are focused knowledge modules that agents load on demand when a task calls for specialized expertise. Unlike agents — which handle broad domains — each skill carries a precise, self-contained body of knowledge: guidelines, command patterns, workflow rules, or design references. When you ask an agent to do something within a skill's domain, the agent pulls that skill in automatically and applies its knowledge before responding. You never need to name or invoke a skill yourself.

## How Skills Work

Skills live in the `skills/` directory of the Naimur OpenCode Agents pack. Each skill is a folder containing a `SKILL.md` file with two things: a short frontmatter block that declares the skill's `name` and `description`, and the actual knowledge content the agent reads at load time.

Agents declare which skills they are permitted to load in their frontmatter `permission` block:

```yaml
permission:
  skill:
    customize-opencode: allow
    unity-cli-helper: allow
```

Only skills listed as `allow` can be loaded by that agent. If you use a global `opencode.json` to set `skill.*` to `deny` by default, every skill must be explicitly opted in per agent — nothing loads silently.

Agents decide *when* to load a skill based on the task. The agent's own instructions describe the exact conditions: for example, the unity agent loads `unity-cli-helper` only for CLI, Editor, module, license, CI, or diagnostic commands — not for every Unity question.

| `unity-cli-helper` | unity agent | Precise Unity CLI flags, module management, license activation, CI patterns, and diagnostics |
